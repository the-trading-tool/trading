AI integration ai_client.py · banner_ai.py · gemini_api.py

The app automatically analyses the latest buy signal with a large language model (LLM) and shows the AI tip on the dashboard. Three providers are supported, with automatic fallback.

Providers and fallback order

ProviderModelsSetup
Groq (preferred)llama-3.3-70b → llama-3.1-8b → gemma2-9bEnter API key groq in the admin panel
Google Geminigemini-2.0-flash-lite → gemini-2.5-flash-lite → gemini-2.5-flashEnter API key gapi in the admin panel
Ollama (local)Any locally installed modelURL + model name as the ollama KSP entry; the Ollama server must be running

Selecting a provider

  1. Admin panel → API access tab → AI provider dropdown
  2. Choice: auto (fallback chain) · groq · gemini · ollama
  3. The setting is stored in config.db under the key ai_provider

What is analysed

The AI receives as context:

  • The latest purchase from trades{year}.db (ticker, buy price, date)
  • 85 indicator values from asset_simulation_all.db
  • Fundamentals from asset_info.db
  • The most recent OHLCV candles from yf_{TICKER}.db

The result (short analysis + assessment) is stored in banner_notes.db and displayed on the dashboard.

No API key → no AI tip, but the app still works fully.
Rate-limit errors (429) are automatically retried with the next available provider in the fallback chain.
