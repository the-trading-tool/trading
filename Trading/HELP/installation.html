Installationsanleitung install.ps1 · install.sh · start.bat

Diese Anleitung führt Schritt für Schritt von einem frischen Rechner bis zur laufenden App mit aktuellen Kursdaten und automatischen Hintergrund-Jobs. Die Installation läuft vollständig lokal – es wird kein Server und kein Cloud-Konto benötigt.

Wer es eilig hat: Schritte 1–5 genügen, damit die App startet. Fehlt beim ersten Start noch die Ticker-Datenbank, übernimmt der Setup-Assistent in der App die Schritte „Ticker-DB anlegen" und „erste Preisdaten laden" (siehe Abschnitt „Setup-Assistent beim ersten Start").

1. Python installieren

Windows

  1. Auf https://www.python.org/downloads/release/python-3119/ die Datei „Windows installer (64-bit)" (python-3.11.9-amd64.exe) herunterladen – nicht die win32-Version.
  2. Installer starten und ganz unten das Häkchen „Add python.exe to PATH" setzen.
  3. „Install Now" klicken, abwarten, „Close".
  4. Kontrolle in einer neuen PowerShell: py -3.11 --version → Python 3.11.x.

Linux

# Ubuntu / Debian
sudo apt update && sudo apt install -y python3.11 python3.11-venv python3-pip git

# Fedora / RHEL
sudo dnf install -y python3.11 git

# Kontrolle
python3.11 --version
Für TA-Lib braucht Linux zusätzlich die C-Bibliothek (libta-lib-dev bzw. ta-lib-devel). Ohne sie läuft die App trotzdem, einige Indikatoren fehlen dann. Unter Windows lädt der Installer ein vorkompiliertes Paket.

2. Programmcode herunterladen

Variante A – mit Git (empfohlen, erleichtert Updates)

git clone https://github.com/the-trading-tool/trading
cd trading/Trading

Variante B – als ZIP

  1. https://github.com/the-trading-tool/trading öffnen → grüner Button „Code" → „Download ZIP".
  2. ZIP entpacken, z. B. nach C:\Trading.
  3. In den Unterordner Trading wechseln – dort liegt asset_analyzer.py. Alle folgenden Befehle laufen in diesem Ordner.
Der Installer prüft, ob asset_analyzer.py im aktuellen Ordner liegt, und bricht sonst mit „Bitte den Installer aus dem Trading-Verzeichnis heraus starten" ab.

3. Installer ausführen

Windows (PowerShell)

  1. Im Ordner Trading mit Shift + Rechtsklick auf eine freie Stelle → „PowerShell-Fenster hier öffnen" (bzw. „In Terminal öffnen").
  2. Skriptausführung für diese Sitzung erlauben: 
    Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process
  3. Installer starten: 
    .\install.ps1

Linux / macOS (Terminal)

chmod +x install.sh
./install.sh

4. Admin-Benutzer anlegen

In Phase 2 fragt der Installer den ersten Benutzer ab:

Admin-Benutzername (Standard: admin):     ← Enter übernimmt „admin"
E-Mail-Adresse (Standard: admin@localhost):
Passwort:                                  ← mind. 8 Zeichen, Eingabe bleibt unsichtbar
Passwort bestaetigen:

Benutzernamen dürfen nur Buchstaben, Ziffern und _ enthalten (3–32 Zeichen). Gespeichert wird ausschließlich ein bcrypt-Hash; dazu ein zufälliger Cookie-Schlüssel je Installation.

config.yaml niemals weitergeben oder in Git einchecken – sie enthält Passwort-Hashes und den Schlüssel, mit dem Login-Cookies signiert werden.

5. Ticker-Stammdaten laden (Pflicht)

Ohne diesen Schritt kennt die App keine Werte – Auswahllisten und Suche bleiben leer.

# Windows
.\install.ps1 -InitInfo

# Linux / macOS
./install.sh --init-info

Das legt die Ticker-Datenbank an und lädt Name, Sektor, Branche und Fundamentaldaten von Yahoo Finance. Einzelne Meldungen wie 404 Not Found sind normal – Yahoo kennt nicht jeden Ticker, der Rest wird trotzdem geladen.

Setup-Assistent beim ersten Start

Startet die App, ohne dass yf_tickers.db existiert, erscheint statt der Startseite ein Assistent:

SchrittWas passiert
WillkommenHaftungsausschluss lesen und bestätigen
1 · Ticker-Datenbankführt seed_db.py aus (DAX-Familie, S&P 500 u. a.) und zeigt das Protokoll live
2 · Erste Preisdatenlädt einen Monat Tageskurse aller Index-Mitglieder (get_asset_data.py /index_member 1d:1mo); kann übersprungen und später nachgeholt werden
Fertig„App starten" – danach erscheint die normale Oberfläche
Fehlt beim Start auch config.yaml (Installer nicht gelaufen), legt die App selbst eine an – mit dem Login admin / changeme. Dieses Passwort sofort ändern; ein neuer Hash entsteht mit
.venv\Scripts\python.exe -c "import bcrypt; print(bcrypt.hashpw(b'NEUESPASSWORT', bcrypt.gensalt()).decode())"
Der Assistent ersetzt nicht Schritt 5: Stammdaten (get_asset_info.py) lädt er nicht. Firmen erscheinen erst in der Auswahl, wenn asset_info.db gefüllt ist.

6. App starten

SystemBefehl
WindowsDoppelklick auf start.bat im Ordner Trading
oder: .venv\Scripts\streamlit.exe run asset_analyzer.py
Windows (Launcher).venv\Scripts\python.exe launcher.py – wartet auf den Server und öffnet den Browser selbst (siehe Hilfe „Anwendung starten")
Linux / macOS.venv/bin/streamlit run asset_analyzer.py

Die App läuft unter http://localhost:8080 (Port aus .streamlit/config.toml). Öffnet sich der Browser nicht von selbst, die Adresse manuell eingeben. Beenden: Terminal-Fenster schließen bzw. Strg + C.

7. Vollständige Daten laden (empfohlen)

Für Charts über mehrere Jahre, Backtests, Strategie-Suche und Signale braucht die App die volle Kurshistorie und die berechneten Indikatoren. Die Daten entstehen in drei Stufen:

StufeSkriptDatenbankDanach sichtbar
1get_asset_data.pyyf_tickers.db, yf_<TICKER>.dbMärkte und Kurscharts
2get_asset_info.pyasset_info.dbFirmenauswahl, Volltextsuche, Fundamentaldaten
3asset_perf2.pyasset_simulation_*.dbScores, Buy/Sell-Signale, Kennzahlen, Screener

Alles in einem Durchgang:

# Windows
.\install.ps1 -Init

# Linux / macOS
./install.sh --init

Oder einzeln (Windows-Pfade; unter Linux .venv/bin/python):

.venv\Scripts\python.exe get_asset_data.py /index_member 1m:7d 60m:60d 1d:max 1mo:max
.venv\Scripts\python.exe get_asset_data.py /index 1m:7d 60m:60d 1d:max 1mo:max
.venv\Scripts\python.exe asset_perf2.py init /worker:2
Der vollständige Download dauert Stunden. Yahoo begrenzt die Abrufrate – bei HTTP 429 einfach später erneut starten, bereits geladene Daten bleiben erhalten. Wochen- und andere Intervalle werden lokal aus Tages-/Stundendaten berechnet und müssen nicht geladen werden.

8. Hintergrund-Jobs einschalten (empfohlen)

Damit Kurse, Indikatoren und Signale täglich aktuell bleiben, hat der Installer in Phase 1F bereits einen Job-Plan in scheduler.db angelegt (Intraday-/Tageskurse je Region, Indikatorberechnung abends, Stammdaten sonntags, Fear-&-Greed-Log, Cache-Vorwärmung, Datenfrische-Prüfung). Ausgeführt werden die Jobs vom Scheduler-Daemon:

# Windows
.venv\Scripts\python.exe schedserver.py

# Linux / macOS
.venv/bin/python schedserver.py
  • Der Prozess muss dauerhaft laufen – für den Autostart z. B. eine Aufgabe in der Windows-Aufgabenplanung „Bei Anmeldung" bzw. einen systemd-User-Dienst anlegen.
  • Jobs ansehen, aktivieren oder ändern: Admin → Scheduler.
  • Angelegt, aber ausgeschaltet sind Standby (Ruhezustand am Abend), die Aufhol-Läufe (catchup) und die Order-Vorbereitung – bei Bedarf im Scheduler aktivieren.
  • Bewusst gar nicht angelegt sind die order-ausführenden Jobs (Trailing-Stop, Order-Ausführung) – sie brauchen Broker-Zugang und einen Benutzer und werden bei Bedarf selbst angelegt.
Empfohlene Zeitpläne und Alternativen mit Aufgabenplanung/cron: Hilfe „Setup & Scheduler (Empfehlungen)" und „Scheduler-Daemon (schedserver.py)".

10. Aktualisieren

git pull
.venv\Scripts\python.exe -m pip install -r requirements.txt --prefer-binary

Danach die App neu starten. Bei ZIP-Installationen das neue ZIP über den alten Ordner entpacken – .venv, database/, config.yaml und logs/ bleiben erhalten. Ein erneuter Lauf von install.ps1 / install.sh ist ebenfalls gefahrlos.

Pakete immer mit .venv\Scripts\python.exe -m pip … installieren, nicht mit einem System-Python – sonst landen sie in der falschen Umgebung.
