Setup & Scheduler

Diese Seite fasst zusammen, in welcher Reihenfolge die App initial eingerichtet wird und welche CLI-Skripte danach regelmäßig im Hintergrund laufen sollten, damit Kursdaten, Indikatoren und Signale immer aktuell sind.

1. Erstinstallation (einmalig)

  1. python seed_db.py – Ticker-Datenbank mit Index-Mitgliedern anlegen
  2. python get_asset_info.py – Fundamentaldaten laden
  3. python get_asset_data.py 1d:2y – historische Tageskurse laden
  4. python asset_perf2.py – Indikatoren & OVT-Scores berechnen
  5. streamlit run asset_analyzer.py – App starten
Details zu jedem Schritt siehe Hilfe „Datenbank initialisieren (seed_db.py)".

Handelszeiten beachten: Xetra schließt um 17:30 Uhr MEZ, die NYSE um 22:00 Uhr MEZ (16:00 Uhr ET, ohne Sommerzeit-Anpassung ggf. ±1 Stunde). Trading-Agent und Stop-Loss-Prüfung sollten nur innerhalb dieses Fensters laufen, der tägliche Datenabruf danach.

3. Zwei Wege, Jobs zu planen

VarianteVorteileNachteile
schedserver.py (App-intern)Jobs bequem im Admin-Panel einrichten, läuft plattformunabhängig, Status in scheduler.dbmuss als Dauerprozess laufen – nach Neustart manuell oder per Autostart wieder anstoßen
Betriebssystem-Scheduler (Task Scheduler / cron)läuft zuverlässig auch ohne offene App, übersteht Neustarts automatisch, Standard-ToolingJobs werden außerhalb der App konfiguriert (Textdateien / GUI)
Nur einen der beiden Wege für denselben Job verwenden – sonst werden z. B. Trading-Orders doppelt ausgelöst.

4. Windows – Aufgabenplanung (Task Scheduler)

Beispiele mit schtasks (PowerShell/CMD als Administrator). <APP> = Installationsverzeichnis, z. B. C:\Users\kurt\Claude\Trading:

# Tageskurse aktualisieren (Mo-Fr, 18:00 Uhr)
schtasks /create /tn "Trading-DailyData" /tr "\"<APP>\.venv\Scripts\python.exe\" \"<APP>\get_asset_data.py\" 1d:5d" /sc weekly /d MON,TUE,WED,THU,FRI /st 18:00

# Indikatoren neu berechnen (Mo-Fr, 22:30 Uhr)
schtasks /create /tn "Trading-Perf" /tr "\"<APP>\.venv\Scripts\python.exe\" \"<APP>\asset_perf2.py\"" /sc weekly /d MON,TUE,WED,THU,FRI /st 22:30

# Signal-Benachrichtigung (Mo-Fr, 22:45 Uhr)
schtasks /create /tn "Trading-Notify" /tr "\"<APP>\.venv\Scripts\python.exe\" -m tradinglib.signal_notifier" /sc weekly /d MON,TUE,WED,THU,FRI /st 22:45

# Trading-Agent alle 15 Minuten (Basis-Trigger; Zeitfenster 09:00-22:00 im
# Trigger-Editor der Aufgabenplanung über "Wiederholen alle: 15 Min" /
# "Dauer: 13 Std" einstellen)
schtasks /create /tn "Trading-Agent" /tr "\"<APP>\.venv\Scripts\python.exe\" \"<APP>\run_agent.py\" --notify" /sc daily /st 09:00

# Stop-Loss-Prüfung alle 15 Minuten (gleiches Prinzip wie oben)
schtasks /create /tn "Trading-StopLoss" /tr "\"<APP>\.venv\Scripts\python.exe\" \"<APP>\check_stoploss.py\" --notify" /sc daily /st 09:00
Für die beiden „alle 15 Minuten"-Jobs lässt sich das Wiederholungsintervall und die Endzeit am einfachsten nachträglich in der grafischen Aufgabenplanung (taskschd.msc) im Reiter Trigger → Bearbeiten → Aufgabe wiederholen alle: 15 Minuten, für die Dauer von: 13 Stunden setzen. Alternativ existieren run_agent.bat / check_stoploss.bat als fertige Wrapper für solche Aufgaben.

5. Linux – Cron

crontab -e, <APP> = Installationsverzeichnis:

# Tageskurse aktualisieren (Mo-Fr 18:00)
0 18 * * 1-5 cd <APP> && .venv/bin/python get_asset_data.py 1d:5d

# US-Werte nach NYSE-Schluss (Mo-Fr 22:15)
15 22 * * 1-5 cd <APP> && .venv/bin/python get_asset_data.py 1d:5d /index_member:SPX

# Indikatoren neu berechnen (Mo-Fr 22:30)
30 22 * * 1-5 cd <APP> && .venv/bin/python asset_perf2.py

# Signal-Benachrichtigung (Mo-Fr 22:45)
45 22 * * 1-5 cd <APP> && .venv/bin/python -m tradinglib.signal_notifier

# Trading-Agent alle 15 Min, 09-22 Uhr (Mo-Fr)
*/15 9-22 * * 1-5 cd <APP> && .venv/bin/python run_agent.py --notify

# Stop-Loss-Prüfung alle 15 Min, 09-22 Uhr (Mo-Fr)
*/15 9-22 * * 1-5 cd <APP> && .venv/bin/python check_stoploss.py --notify

# Fundamentaldaten wöchentlich (So 06:00)
0 6 * * 0 cd <APP> && .venv/bin/python get_asset_info.py

# ISIN-Lücken monatlich (1. des Monats, 03:00)
0 3 1 * * cd <APP> && .venv/bin/python backfill_isin.py /limit:200

6. Externe Dienste: Registrierung & Empfehlungen

Datenquelle (Marktdaten)

  • Yahoo Finance (Standard): keine Registrierung nötig, sofort einsatzbereit. Es handelt sich aber um eine inoffizielle Schnittstelle (yfinance scrapt öffentliche Endpunkte) – ohne SLA, mit gelegentlichen Sperren oder Rate-Limits, besonders bei vielen automatisierten Hintergrund-Läufen.
  • Financial Modeling Prep (FMP), empfohlen für Hintergrund-Jobs: kostenlosen API-Key auf financialmodelingprep.com registrieren, als KSP-Eintrag fmp hinterlegen und im Konfigurationsdialog (🏵) als aktiven Datenprovider auswählen. Details siehe Hilfe „Datenquellen (Yahoo / FMP / EODHD)".
Empfehlung: Für regelmäßige, automatisierte Abrufe (siehe Tabelle oben) FMP als primäre Quelle nutzen und Yahoo Finance nur als Fallback betrachten – z. B. wenn FMP-Limits (250 Anfragen/Tag im Free-Tier) erreicht sind oder kein API-Key hinterlegt ist. So bleibt die App auch bei einer Yahoo-Sperre funktionsfähig.
