Data sources tradinglib/providers/

All price and OHLC data flows through a swappable provider layer. By default Yahoo Finance (via yfinance) is used. Alternatively, Financial Modeling Prep (FMP) or EOD Historical Data (EODHD) can be enabled as the data source – e.g. when Yahoo is temporarily blocked or rate-limited.

Switching provider

Via the 🏵 button (configuration, visible to admins only) → Data provider section:

  • Active data provider: yahoo (default), fmp or eodhd
  • The choice applies globally to all modules that fetch price data (fetch_data.py, market_data.py, get_asset_data.py …)
  • If the API key for fmp/eodhd is missing, the app falls back to Yahoo automatically (no error, just a log entry)
Recommendation – use Yahoo only as a fallback: Yahoo Finance is connected via yfinance, an unofficial interface without an SLA. Frequent automated background fetches (see the "Setup & Scheduler" help) risk blocks or rate limits. For recurring jobs, therefore set up FMP as the primary provider and keep Yahoo only as a fallback in case FMP limits are reached or no API key is stored.

Financial Modeling Prep (FMP)

Prerequisite: API key

  • Create a free API key at financialmodelingprep.com
  • In the admin panel under API access, create a KSP entry fmp, password = the API key
  • In the configuration dialog a green note "API key found" appears once the entry is recognised
  • Use 🔌 Test connection to check access immediately

Ticker compatibility

FMP partly uses different ticker symbols than Yahoo Finance. The conversion happens automatically:

Security typeYahoo symbolFMP symbol
US stocksAAPLAAPL (identical)
German stocks (Xetra)SAP.DESAP.F
CryptocurrenciesBTC-USDBTCUSD
Indices^GDAXI, ^SPX, ^TNXidentical
Other exchanges—mostly identical, otherwise manually overridable

Manual ticker overrides

If the automatic conversion does not fit a ticker, a custom mapping Yahoo ticker → FMP ticker can be added in the configuration dialog. The list is stored under _app:fmp_ticker_overrides in config.db and can be removed again via the ✕ symbol.

Rate limits (free FMP plan): 250 requests/day, 10 requests/minute. With intensive use (e.g. get_asset_data.py /all) these limits can be reached quickly.

EOD Historical Data (EODHD)

Prerequisite: API key

  • Create an API key at eodhd.com
  • In the admin panel under API access, create a KSP entry eodhd, password = the API key
  • Otherwise identical to FMP: a green note confirms the key, 🔌 Test connection checks access

Ticker compatibility

EODHD always uses a CODE.EXCHANGE format – even US symbols need a suffix. The conversion happens automatically:

Security typeYahoo symbolEODHD symbol
US stocksAAPLAAPL.US
German stocks (Xetra)SAP.DESAP.XETRA
LondonVOD.LVOD.LSE
Indices^GSPC, ^GDAXIGSPC.INDX, GDAXI.INDX
CryptocurrenciesBTC-USDBTC-USD.CC
ForexEURUSD=XEURUSD.FOREX
Other exchangesAIR.PA, NESN.SWmostly identical (.AX→.AU, .SS→.SHG etc. are mapped)
FuturesCT=Fno reliable equivalent → override manually

Intervals

EODHD serves only 1m, 5m and 1h intraday bars. Other intervals are aggregated locally from the next finer resolution (e.g. 15m from 5m bars), so callers get the granularity they asked for. History per interval: 1m ≈ 120 days, 5m ≈ 600 days, 1h ≈ 7200 days – earlier start dates are clamped automatically. Daily/weekly/monthly data (1d/1wk/1mo) is unlimited.

Rate limits: the free EODHD plan allows only 20 requests/day (for testing); paid plans allow 100,000 requests/day. One EOD fetch = 1 request per ticker.

Manual ticker overrides

As with FMP: a custom mapping Yahoo ticker → EODHD ticker can be added in the configuration dialog. Stored under _app:eodhd_ticker_overrides in config.db.

All providers deliver data in the same format (Open/High/Low/Close/Volume, like yfinance). Switching provider requires no change to existing databases or analyses – only future fetches use the new source.
ISIN resolution: FMP and EODHD can both resolve ISINs to tickers (used by the Scalable import and backfill_isin.py). The active data provider is preferred; if no key is stored there, the other one is used. An EODHD key alone is therefore sufficient – an additional FMP key is not required.
