Setup & Scheduler

This page summarises the order in which the app is initially set up and which CLI scripts should then run regularly in the background so that price data, indicators and signals stay up to date.

1. First installation (once)

  1. python seed_db.py – create the ticker database with index members
  2. python get_asset_info.py – load fundamentals
  3. python get_asset_data.py 1d:2y – load historical daily prices
  4. python asset_perf2.py – compute indicators & OVT scores
  5. streamlit run asset_analyzer.py – start the app
For details on each step see the "Initialise database (seed_db.py)" help.

2. Recommended background jobs

WhenCommandPurpose

Mon–Fri, every 15 min, 09:00–22:00python check_stoploss.py --notifyCheck the ATR trailing stop for open positions

Once a monthpython backfill_isin.py /limit:200Gradually fill in missing ISINs
Mind the trading hours: Xetra closes at 17:30 CET, the NYSE at 22:00 CET (16:00 ET; without DST adjustment possibly ±1 hour). The trading agent and stop-loss check should only run within this window, the daily data fetch afterwards.

3. Two ways to schedule jobs

VariantAdvantagesDisadvantages
schedserver.py (in-app)Configure jobs conveniently in the admin panel, runs platform-independently, status in scheduler.dbmust run as a continuous process – after a restart, trigger it again manually or via autostart
OS scheduler (Task Scheduler / cron)runs reliably even without the app open, survives restarts automatically, standard toolingjobs are configured outside the app (text files / GUI)
Use only one of the two ways for the same job – otherwise, for example, trading orders would be triggered twice.

4. Windows – Task Scheduler

Examples with schtasks (PowerShell/CMD as administrator). <APP> = installation directory, e.g. C:\Users\kurt\Claude\Trading:

# Update daily prices (Mon-Fri, 18:00)
schtasks /create /tn "Trading-DailyData" /tr "\"<APP>\.venv\Scripts\python.exe\" \"<APP>\get_asset_data.py\" 1d:5d" /sc weekly /d MON,TUE,WED,THU,FRI /st 18:00

# Recompute indicators (Mon-Fri, 22:30)
schtasks /create /tn "Trading-Perf" /tr "\"<APP>\.venv\Scripts\python.exe\" \"<APP>\asset_perf2.py\"" /sc weekly /d MON,TUE,WED,THU,FRI /st 22:30

# Signal notification (Mon-Fri, 22:45)
schtasks /create /tn "Trading-Notify" /tr "\"<APP>\.venv\Scripts\python.exe\" -m tradinglib.signal_notifier" /sc weekly /d MON,TUE,WED,THU,FRI /st 22:45

# Trading agent every 15 minutes (base trigger; set the 09:00-22:00 window in the
# Task Scheduler trigger editor via "Repeat every: 15 min" / "Duration: 13 hours")
schtasks /create /tn "Trading-Agent" /tr "\"<APP>\.venv\Scripts\python.exe\" \"<APP>\run_agent.py\" --notify" /sc daily /st 09:00

# Stop-loss check every 15 minutes (same principle as above)
schtasks /create /tn "Trading-StopLoss" /tr "\"<APP>\.venv\Scripts\python.exe\" \"<APP>\check_stoploss.py\" --notify" /sc daily /st 09:00
For the two "every 15 minutes" jobs, the repeat interval and end time are most easily set afterwards in the graphical Task Scheduler (taskschd.msc) under Trigger → Edit → Repeat task every: 15 minutes, for a duration of: 13 hours. Alternatively, run_agent.bat / check_stoploss.bat exist as ready-made wrappers for such tasks.

5. Linux – Cron

crontab -e, <APP> = installation directory:

# Update daily prices (Mon-Fri 18:00)
0 18 * * 1-5 cd <APP> && .venv/bin/python get_asset_data.py 1d:5d

# US names after NYSE close (Mon-Fri 22:15)
15 22 * * 1-5 cd <APP> && .venv/bin/python get_asset_data.py 1d:5d /index_member:SPX

# Recompute indicators (Mon-Fri 22:30)
30 22 * * 1-5 cd <APP> && .venv/bin/python asset_perf2.py

# Signal notification (Mon-Fri 22:45)
45 22 * * 1-5 cd <APP> && .venv/bin/python -m tradinglib.signal_notifier

# Trading agent every 15 min, 09-22h (Mon-Fri)
*/15 9-22 * * 1-5 cd <APP> && .venv/bin/python run_agent.py --notify

# Stop-loss check every 15 min, 09-22h (Mon-Fri)
*/15 9-22 * * 1-5 cd <APP> && .venv/bin/python check_stoploss.py --notify

# Fundamentals weekly (Sun 06:00)
0 6 * * 0 cd <APP> && .venv/bin/python get_asset_info.py

# ISIN gaps monthly (1st of the month, 03:00)
0 3 1 * * cd <APP> && .venv/bin/python backfill_isin.py /limit:200

6. External services: registration & recommendations

Data source (market data)

  • Yahoo Finance (default): no registration needed, ready to use immediately. However, it is an unofficial interface (yfinance scrapes public endpoints) – no SLA, with occasional blocks or rate limits, especially with many automated background runs.
  • Financial Modeling Prep (FMP), recommended for background jobs: register a free API key at financialmodelingprep.com, store it as a KSP entry fmp and select it as the active data provider in the configuration dialog (🏵). For details see the "Data sources (Yahoo / FMP)" help.
Recommendation: For recurring, automated fetches (see the table above) use FMP as the primary source and treat Yahoo Finance only as a fallback – e.g. when FMP limits (250 requests/day on the free tier) are reached or no API key is stored. That keeps the app functional even during a Yahoo block.
