Installation Guide install.ps1 · install.sh · start.bat

This guide takes you step by step from a fresh computer to a running app with current price data and automatic background jobs. Everything runs locally – no server and no cloud account are required.

Overview

#StepRequired?Time (approx.)
1Install Python✅ yes5 min
2Download the program code✅ yes2 min

In a hurry: steps 1–5 are enough to start the app. If the ticker database is still missing on first start, the in-app setup wizard takes over "create ticker DB" and "load first price data" (see section "Setup wizard on first start").

1. Install Python

Windows

  1. From https://www.python.org/downloads/release/python-3119/ download "Windows installer (64-bit)" (python-3.11.9-amd64.exe) – not the win32 version.
  2. Run the installer and tick "Add python.exe to PATH" at the bottom.
  3. Click "Install Now", wait, then "Close".
  4. Check in a new PowerShell: py -3.11 --version → Python 3.11.x.

Linux

# Ubuntu / Debian
sudo apt update && sudo apt install -y python3.11 python3.11-venv python3-pip git

# Fedora / RHEL
sudo dnf install -y python3.11 git

# Check
python3.11 --version
On Linux, TA-Lib additionally needs its C library (libta-lib-dev or ta-lib-devel). The app runs without it, but some indicators are then unavailable. On Windows the installer fetches a prebuilt package.

2. Download the program code

Option A – with Git (recommended, makes updates easier)

git clone https://github.com/the-trading-tool/trading
cd trading/Trading

Option B – as ZIP

  1. Open https://github.com/the-trading-tool/trading → green "Code" button → "Download ZIP".
  2. Unzip, e.g. to C:\Trading.
  3. Change into the Trading subfolder – it contains asset_analyzer.py. All following commands run in this folder.
The installer checks that asset_analyzer.py is in the current folder and aborts otherwise.

3. Run the installer

Windows (PowerShell)

  1. In the Trading folder, Shift + right-click an empty spot → "Open PowerShell window here" (or "Open in Terminal").
  2. Allow scripts for this session: 
    Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process
  3. Start the installer: 
    .\install.ps1

Linux / macOS (terminal)

chmod +x install.sh
./install.sh

What the installer does

PhaseContent
1AFind Python (Windows: py -3.11, otherwise python3.11/python3/python) and verify 64-bit
1BCreate the virtual environment .venv (kept on later runs)
1CUpgrade pip, install TA-Lib and all packages from requirements.txt, download NLTK sentiment data (vader_lexicon)
1DCreate the database/ and logs/ folders
1EGenerate the encryption key database/secret.key for stored API credentials
1FSeed the default background jobs into database/scheduler.db – only if it contains no jobs yet
2Ask for the admin user and create config.yaml (login) – only if it is missing
3with -Seed/-InitInfo/-Init: fill the ticker database yf_tickers.db (seed_db.py)
4Awith -InitInfo/-Init: load master data into asset_info.db (get_asset_info.py)
4Bwith -Init: load the full price history (get_asset_data.py, after confirmation)
4Cwith -Init: compute indicators and scores (asset_perf2.py init)
The installer is repeatable: an existing .venv, config.yaml, secret.key and scheduler jobs are skipped. Before overwriting existing databases it asks (j/N – answer y or j to confirm).

4. Create the admin user

In phase 2 the installer asks for the first user:

Admin-Benutzername (Standard: admin):     ← Enter keeps "admin"
E-Mail-Adresse (Standard: admin@localhost):
Passwort:                                  ← at least 8 characters, input stays hidden
Passwort bestaetigen:

User names may only contain letters, digits and _ (3–32 characters). Only a bcrypt hash is stored, plus a random cookie key per installation. (The installer prompts are in German.)

Never share config.yaml or commit it to Git – it contains password hashes and the key that signs login cookies.

5. Load ticker master data (required)

Without this step the app knows no instruments – selection lists and search stay empty.

# Windows
.\install.ps1 -InitInfo

# Linux / macOS
./install.sh --init-info

This creates the ticker database and loads name, sector, industry and fundamentals from Yahoo Finance. Individual messages like 404 Not Found are normal – Yahoo does not know every ticker; the rest is loaded anyway.

Setup wizard on first start

If the app starts while yf_tickers.db does not exist, a wizard is shown instead of the start page:

StepWhat happens
WelcomeRead and accept the disclaimer
1 · Ticker databaseruns seed_db.py (DAX family, S&P 500 and more) and shows the log live
2 · First price dataloads one month of daily prices for all index members (get_asset_data.py /index_member 1d:1mo); can be skipped and done later
Done"Start app" – the normal interface appears
If config.yaml is missing as well (installer not run), the app creates one itself – with the login admin / changeme. Change this password immediately; create a new hash with
.venv\Scripts\python.exe -c "import bcrypt; print(bcrypt.hashpw(b'NEWPASSWORD', bcrypt.gensalt()).decode())"
The wizard does not replace step 5: it does not load master data (get_asset_info.py). Companies only appear in the selection once asset_info.db is filled.

6. Start the app

SystemCommand
WindowsDouble-click start.bat in the Trading folder
or: .venv\Scripts\streamlit.exe run asset_analyzer.py
Windows (launcher).venv\Scripts\python.exe launcher.py – waits for the server and opens the browser (see help "Starting the app")
Linux / macOS.venv/bin/streamlit run asset_analyzer.py

The app runs at http://localhost:8080 (port from .streamlit/config.toml). If the browser does not open by itself, enter the address manually. To stop: close the terminal window or press Ctrl + C.

7. Load complete data (recommended)

Multi-year charts, backtests, strategy search and signals need the full price history and the computed indicators. The data is built in three stages:

StageScriptDatabaseVisible afterwards
1get_asset_data.pyyf_tickers.db, yf_<TICKER>.dbmarkets and price charts
2get_asset_info.pyasset_info.dbcompany selection, full-text search, fundamentals
3asset_perf2.pyasset_simulation_*.dbscores, buy/sell signals, key figures, screeners

All in one go:

# Windows
.\install.ps1 -Init

# Linux / macOS
./install.sh --init

Or individually (Windows paths; on Linux use .venv/bin/python):

.venv\Scripts\python.exe get_asset_data.py /index_member 1m:7d 60m:60d 1d:max 1mo:max
.venv\Scripts\python.exe get_asset_data.py /index 1m:7d 60m:60d 1d:max 1mo:max
.venv\Scripts\python.exe asset_perf2.py init /worker:2
The full download takes hours. Yahoo rate-limits requests – on HTTP 429 simply restart later; data already loaded is kept. Weekly and other intervals are computed locally from daily/hourly data and need not be downloaded.

8. Enable background jobs (recommended)

To keep prices, indicators and signals current every day, the installer already wrote a job plan into scheduler.db in phase 1F (intraday/daily prices per region, evening indicator run, master data on Sundays, Fear & Greed log, cache warming, data freshness check). The jobs are executed by the scheduler daemon:

# Windows
.venv\Scripts\python.exe schedserver.py

# Linux / macOS
.venv/bin/python schedserver.py
  • The process must keep running – for autostart, create e.g. a Windows Task Scheduler task "At log on" or a systemd user service.
  • View, enable or edit jobs: Admin → Scheduler.
  • Created but disabled: standby (evening hibernate), the catch-up runs (catchup) and order staging – enable them in the scheduler if needed.
  • Deliberately not created at all: the order-executing jobs (trailing stop, order execution) – they need broker access and a user and are set up manually when wanted.
Recommended schedules and alternatives using Task Scheduler/cron: help "Setup & Scheduler" and "Scheduler daemon (schedserver.py)".

10. Updating

git pull
.venv\Scripts\python.exe -m pip install -r requirements.txt --prefer-binary

Then restart the app. For ZIP installations, unzip the new archive over the old folder – .venv, database/, config.yaml and logs/ are kept. Re-running install.ps1 / install.sh is safe as well.

Always install packages with .venv\Scripts\python.exe -m pip …, not with a system Python – otherwise they end up in the wrong environment.
