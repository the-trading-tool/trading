KI-Integration ai_client.py · banner_ai.py · gemini_api.py

Die App analysiert automatisch das letzte Kaufsignal mit einem großen Sprachmodell (LLM) und zeigt den KI-Tipp auf dem Dashboard. Drei Provider werden unterstützt, mit automatischem Fallback.

Provider und Fallback-Reihenfolge

ProviderModelleEinrichtung
Groq (bevorzugt)llama-3.3-70b → llama-3.1-8b → gemma2-9bAPI-Key groq im Admin-Panel eintragen
Google Geminigemini-2.0-flash-lite → gemini-2.5-flash-lite → gemini-2.5-flashAPI-Key gapi im Admin-Panel eintragen
Ollama (lokal)Beliebiges lokal installiertes ModellURL + Modellname als ollama-KSP-Eintrag; Ollama-Server muss laufen

Provider auswählen

  1. Admin-Panel → Tab API-Zugänge → KI-Provider Dropdown
  2. Wahl: auto (Fallback-Kette) · groq · gemini · ollama
  3. Einstellung wird in config.db unter dem Key ai_provider gespeichert

Was analysiert wird

Die KI erhält als Kontext:

  • Letzter Kauf aus trades{Jahr}.db (Ticker, Kaufpreis, Datum)
  • 85 Indikator-Werte aus asset_simulation_all.db
  • Fundamentaldaten aus asset_info.db
  • Letzte OHLCV-Kerzen aus yf_{TICKER}.db

Das Ergebnis (Kurz-Analyse + Einschätzung) wird in banner_notes.db gespeichert und auf dem Dashboard angezeigt.

Kein API-Key vorhanden → kein KI-Tipp, die App funktioniert trotzdem vollständig.
Rate-Limit-Fehler (429) werden automatisch mit dem nächsten verfügbaren Provider in der Fallback-Kette wiederholt.
